## Consolidated Agent Operating Model

### Agent Hierarchy

```
AGENTS.md (root authority)
├── .ai/agents/ (persona definitions)
├── .ai/roles/ (role definitions)
├── .engineering/ (generated coordination — reference only)
├── .cursor/ (local IDE configs — not binding)
└── intelligence/agents/ (runtime AI agents)
```

### Boundary Rules

| Agent | Owns | Does NOT Own |
|-------|------|-------------|
| Workspace Agent (AGENTS.md) | Global instructions, security rules, engineering standards | Specific feature implementation |
| Architecture Reviewer | Architecture decisions, ADR compliance | Code implementation |
| Backend Lead | Backend code quality, patterns, tests | Frontend, infrastructure |
| Execution Orchestrator | Parallel task dispatch, coordination | Individual task execution |
| Intelligence Agents | AI copilot functionality | Business logic outside intelligence |
| Coordinator | Goal-based planning | Direct execution |

### Conflicts Resolved

| Conflict | Resolution |
|----------|------------|
| `.ai/` vs `.cursor/` agent definitions | `.ai/` is authoritative; `.cursor/` is local |
| `.engineering/` generated docs vs actual code | Code (Tier 1) wins; `.engineering/` is reference |
| Multiple "orchestrator" definitions | Execution Orchestrator in `.ai/` is canonical |
| AGENTS.md vs `.ai/roles/` | AGENTS.md is root; `.ai/roles/` are persona definitions |

### Lifecycle

1. **AGENTS.md** is updated by humans or authorized agents
2. **.ai/** configs are maintained by humans
3. **.engineering/** is auto-generated (do not edit manually)
4. **Intelligence agents** are frozen (no changes without PO approval)
5. **.cursor/** is local and not tracked for consistency
